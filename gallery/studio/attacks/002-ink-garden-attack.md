## Curator 裁决说明

### 采纳-立即修（本轮修复）

**A. 视觉质量提升（最高优先级）**

1. **笔触质感（A1/D3）**：当前所有枝条是等宽 `lineTo`，改为沿路径分段变宽（基部粗、梢部细），枝条连接处加微 `shadowBlur` 模拟洇散，部分末梢枝条用降 alpha 模拟干笔飞白。不做完整水墨仿真（那是另一个作品的量级），但要让线条有"笔"的意味。

2. **景深系统（A3）**：植物按 y 坐标分近/中/远三层。远（y 距 groundY 较远，画面上方）：scale 0.6-0.75、墨色淡、无叶细节；中：scale 0.8-0.9；近：scale 1.0、墨色浓、细节完整。制造"远树无枝"的空气透视。

3. **DPR 适配（A7）**：`canvas.width = W * dpr`，`ctx.setTransform(dpr,0,0,dpr,0,0)`，与山居一致。

4. **梅花重画（A5）**：五个椭圆实心瓣改为淡墨圈瓣（stroke 不 fill）+ 浓墨点蕊，竹叶改为成组笔触而非单片椭圆。

5. **风系统改进（A4/C5/D5）**：`wind.direction` 真正乘入枝条偏移；用两层 sin 叠加（不同频率）替代单层正弦；阵风用 e^-t 包络而非线性 lerp。

6. **远山修正（A10）**：alpha 0.12 → 0.22，颜色从青绿 `#8a9a8a` 改为暖灰墨 `#9a9080`，删除无效微动画。

7. **落叶改进（A11）**：改为柳叶形（两头尖），翻转时用 scaleX 模拟叶面翻背，加微旋转加速度。

**B. 交互安全**

8. **清园确认（I1）**：点击"清"后按钮变为"确认？"状态，2秒内再点才执行，否则恢复。不使用 `confirm()` 弹窗（破坏意境），用按钮状态变化。

9. **长按改进（I5/I12）**：阈值 300ms → 500ms；长按时在触点显示圆形进度环（canvas 绘制），满环才触发移除；移除距离从 60px 缩小到 40px 减少误删。

10. **移动端按钮（I2）**：38px → 44px，gap 4px → 8px。

11. **Tooltip/标签（I4）**：移动端按钮下方常驻极小字标签（竹/松/柳/梅/兰/枯/缘/清/风），桌面端保留 hover tooltip。

12. **Hint 改进（I3/I12）**：字号增大、颜色加深；首次加载时 hint 有 3 次呼吸闪烁；加一句"长按/右键 可除草"。

13. **植物上限（A2/C7/I6）**：软上限 60 株，达到后新种替换最老的（带淡出），右上角提示"园中草木已盛"。

14. **滚动指示（I11）**：底部栏右侧加渐隐遮罩暗示可滚动。

**C. Bug 与性能**

15. **颜色预解析（C3）**：species 定义时预解析 hex 为 `{r,g,b}`，不在 draw 循环中 parseInt。
16. **DOM 缓存（C4）**：启动时缓存所有 getElementById 结果；风速指示器降频到 200ms 更新。
17. **resize 修正（C6）**：记录植物相对 groundY 的偏移比，resize 时按新 groundY 重算 y。
18. **clearGarden 修正（C8/I9）**：不清空 particles（让淡出植物的粒子自然消亡），清空 fallingLeaves。
19. **死代码清理（C9/C12/C13）**：删 plantAt 前两行钳制、parentId 参数、sp_growSpeed 包装。
20. **Vignette 缓存（C10）**：resize 时生成到离屏 canvas，主循环直接 drawImage。
21. **落叶阻尼（C11）**：`l.vx *= 0.98` 每帧。
22. **RAF 暂停（C15）**：visibilitychange 隐藏时 cancelAnimationFrame，可见时恢复。
23. **starter 布局（A8/D6）**：三株初始植物改为非对称位置（0.2/0.55/0.82），中间株略高。

### 记录-下次再说（不本轮修）

- **C1/C2 架构重构**：物种 if-else 改数据驱动、Plant 与全局粒子解耦——等加第7种植物时再做，现在改收益不够
- **C14 魔法数字**：集中常量化，不影响功能，下次重构时一起
- **A9 UI 重设计**：毛玻璃改题跋式——这是全系列的 UI 语言问题，不该墨园单独改，Studio 级决策
- **I7 拖拽移动**：种错可拖动调整——好功能但量大，留作下次
- **I8 植物预览**：按钮内微缩剪影——精致但非必需
- **I10 导出/成就**：PNG 导出/留影——好功能，留作下次
- **D4 生命周期**：植物发芽→繁茂→枯萎→消亡——这是一个全新作品的方向（"枯荣"？），不是墨园的补丁

### 不采纳（附理由）

- **D1 "没有第二次打开的理由"**：墨园定位是生成艺术玩具，不是游戏。它的价值在于"每次种植都是独一无二的画面"，和水墨粒子一样是冥想性的互动体验，不需要重玩目标。山居的经营深度是另一种作品形态，不必每件都追求。
- **D2 "递归树是 Hello World"**：每一种创意编程技法都有经典原型。油画笔刷也存在了几百年。价值在于参数化的六种植物形态、水墨美学语言和互动体验的结合，而非算法本身的新颖性。
- **A6 印章字体**：马善政体是全系列七件作品的统一印章字体，单独改墨园会破坏系列一致性。篆书确实更合制，但这是 Studio 级决策，需要在所有作品上统一迁移。记录为 Builder 模块改进候选。

## R2 Curator 裁决说明

### 对魔鬼代言人的最终回应

魔鬼代言人两轮坚持的P0"墨是涂层不是媒介"——我**仍然不采纳为修复项，但承认它是对的**。

这不是回避，而是定位判断：
- 真正的纸墨交互模拟（纤维渗透、流体扩散、干笔丝缕）是一个独立的渲染工程，可能需要WebGL shader或离屏canvas像素级操作，工作量是当前作品的3-5倍
- 墨园的定位是"算法生成+水墨意境的互动玩具"，不是"水墨物理仿真器"
- 但魔鬼代言人捅到了真实的天花板：**Canvas 2D lineTo确实有其表达上限**。这记录为Builder层的核心挑战——未来如果要做真正的水墨渲染，需要一个独立的ink-renderer模块

美术指导抓出的两个P0（接点跳变、梅花不可见）是R1修复引入的实现bug，不是方向错误，必须修。

### 采纳-立即修（R2修复）
