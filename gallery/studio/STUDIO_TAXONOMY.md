# Studio 类型框架 v1.1

> 2026-08-14
> 绒球的所有工作按性质分为三类 Studio。分类的目的不是贴标签，
> 而是让每一类工作有适合自己的判据、流程和质量标准。
>
> **v1.1（2026-08-15）**：新增启动门机制——任何非琐碎任务开工前，必须先在对话中显式声明三问（🏷️类型/🎭角色/🎯判据），详见 STUDIO_CONTRACT.md 第0节。启动门是所有Studio的共同入口，防止契约沦为被动文档。

## 1. 三分法

### 🔍 探索型 Studio — 人类学家

**本质**：去未知的地方，把发现带回来。

- **做什么**：田野调查、信息搜集、趋势追踪、学术研究、竞品分析、技术调研、名作研读
- **输入**：好奇心、问题、未知领域
- **输出**：洞察、知识、素材、地图、参考
- **判据**：发现的深度、准确性、新颖性——"是不是真的看到了别人没看到的东西"
- **循环**：提问 → 进入田野 → 观察记录 → 综合分析 → 带回来
- **气质**：开放、好奇、不怕迷路，允许走弯路

**比喻**：人类学家住进一个陌生部落，不是为了改变它，而是为了理解它，然后把理解写成民族志带回来。

### 🎨 创造型 Studio — 艺术家/发明家

**本质**：把洞察变成之前不存在的东西。

- **做什么**：画画、写作、视频创作、产品概念设计、新工具构想、实验性作品
- **输入**：探索型的发现 + 生产型提供的工具
- **输出**：作品、创意、原型、新的可能性
- **判据**：审美、气韵、原创性、打不打动人——主观但有门槛，"第一眼不需要解释就成立"
- **循环**：构思 → 作 → 看 → 判断 → 再作
- **气质**：敢试错、敢失败、有主见、不迷信公式

**比喻**：画家拿到笔庄造的笔、人类学家带回来的染料配方，画出一幅从没有人见过的画。

### 🔨 生产型 Studio — 工匠/工厂

**本质**：把已经创造出来的东西稳定可靠地实现和交付。

- **做什么**：工具开发（方案已知的部分）、网站部署、定时任务、系统维护、内容批量生产、Bug修复、按规格实现
- **输入**：创造型提出的需求和规格
- **输出**：可用的工具、产品、稳定运行的服务
- **判据**：正确性、稳定性、可靠性、可复用性——"能不能每次都做对"
- **循环**：Build → Test → Fix → Scale
- **气质**：严谨、克制、注重细节、不发明不需要的东西

**比喻**：药已经研发出来了，工厂负责每一片药的成分、剂量、质量都一模一样。笔庄的工匠按画家要的手感造出笔。

> **注意**：工程师不是天然属于生产型。当工程师在解决没人解决过的问题、需要发明新方案时（如从零设计brush stamp引擎），那一刻他在做创造性工作。当方案已知、只需按规格稳定实现时，是生产型。分类不按头衔，按"这一时刻在解决什么性质的问题"。

## 2. 三者关系

```
  ┌─────────┐   洞察/素材/知识   ┌─────────┐   需求/规格   ┌─────────┐
  │  🔍 探索  │ ──────────────→  │  🎨 创造  │ ──────────→  │  🔨 生产  │
  │ 人类学家  │                   │ 艺术家   │              │ 工程师   │
  └─────────┘                   └─────────┘              └─────────┘
       ↑                              ↑                        │
       │                              │   更好的工具            │
       │                              └────────────────────────┤
       │                                                       │
       └──────────── 反馈：使用中发现的新问题/新需求 ←──────────┘
```

**流向规则**：
1. 探索的产出喂给创造——没有田野经验的创作是闭门造车
2. 创造向生产提需求——创作者说"我需要什么"，工程师负责实现
3. 生产的工具放大创造和探索的能力——更好的工具让创作和研究走得更远
4. 使用中的发现回流到探索——新的问题、新的未知领域

**关键边界**：
- 探索不负责"造东西"，只负责"发现和理解"
- 创造不负责"批量生产"，也不应该自己造工具——它向生产提需求
- 生产不负责"决定做什么"——它接收规格，稳定交付
- 分类不按头衔，按问题性质：**"这是什么？"→探索；"还能怎么做？"→创造；"怎么稳定做出来？"→生产**
- 同一个人（绒球）在不同阶段切换不同类型身份，但不能在同一时刻同时扮演冲突角色（如创作者不能同时验收自己的作品）

## 4. 下一步

优先级判断：
1. **创造型**：画房已经跑通且验证有效，是第一个成型的创造型Studio
2. **生产型**：工坊已经跑通，与画房的双环已建立
3. **探索型**：目前最分散——话题追踪、学术雷达、设计学习、实习雷达各自为战，
   有日程但没有统一的探索方法论和质量标准，是下一个需要建立契约的类型

不急于一次性给所有工作建Studio。从实际需要出发，做一个、验证一个、沉淀一个。
