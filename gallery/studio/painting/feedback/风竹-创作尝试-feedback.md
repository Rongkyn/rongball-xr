# 风竹/风兰创作尝试 — 工具缺陷反馈

> 画房 → 工坊
> 2026-08-14

## 创作意图

尝试画"风中之竹"或"风中之兰"，探索墨园在动态题材上的表现力。
参考了吴镇《墨竹谱》、柯九思墨竹真迹。

## 尝试过程

### 1. 风竹（si=0）
- **结果**：三丛竹子看起来像简笔画/蜘蛛，竹竿太直太细，叶子像小刺球
- **问题**：P3已记录的算法根本缺陷——竹子Y形分叉+均匀分布，完全没有宋画墨竹的笔意
- **评分**：2/10，无法通过7分门槛

### 2. 枯木（si=5）
- **结果**：需要40秒才长完，最终像花菜/西兰花，对称Y形分叉+伞状冠
- **问题**：通用递归分叉算法不适合木本植物；淡墨(INK.dan)在宣纸上太浅
- **评分**：2/10

### 3. 风柳（si=2）
- **结果**：骨架比竹/枯好，有拱形枝条和垂丝
- **问题**：
  - 整树高约150px，在1920px画布上太小
  - 垂丝太细太淡，像雨丝不像柳条
  - compose模式没有像兰花那样的倍率放大
- **评分**：4/10，有潜力但当前不可用

### 4. 风兰（si=4）
- **结果**：兰叶笔意出来了（飞白质感），但每丛只有5片叶（宋画标准7-9片）
- **问题**：
  - 随机种子决定一切，无法通过API控制叶数/角度/花位置
  - V形对称喷泉构图，无法主动打破对称
  - 花的位置在叶基附近而非叶上半段
- **评分**：5/10

### 5. 双丛兰
- **结果**：构图比单丛好，有左右呼应
- **问题**：
  - 两丛太相似，像复制粘贴，缺少主次对比
  - 每丛仍然只有5片叶
  - 无法控制两丛之间的姿态差异
- **评分**：5.5/10

## 工具缺陷（按严重程度排序）

### P0：compose API控制力严重不足
**现象**：`__inkPlant(x, y, si)` 只能指定位置和物种，无法控制：
- 叶数/分枝数
- 每片叶的角度、长度、弯度
- 花的位置和数量
- 随机种子
- 构图参数（compose模式的1.75倍叶长等参数硬编码在buildOrchid中）

**影响**：画房原则2.3"不选彩票要作画"无法执行。创作者无法主动决定构图，只能在随机结果中挑选，这本质上是买彩票而非作画。幽兰当时能出好作品是因为直接改了代码参数，不是通过创作API。

**建议方向**：
- compose API增加可选的构图参数对象：`__inkPlant(x, y, si, { leafCount, leafAngles, sag, seed, ... })`
- 或者更彻底：按照今天讨论的Command Bus架构，把每次种植物分解为可组合的Command（放一笔、加一叶、调参数），让AI和人都能通过Command序列精确控制构图

### P1：竹/松/枯的生长算法根本缺陷
**现象**：所有木本植物都使用通用递归分叉算法，产生对称Y形结构
**影响**：竹/松/枯三个物种无法产出7分以上作品
**状态**：P3已记录，优先级低
**建议**：需要重写，参考buildOrchid和buildWillow的物种专用构建方式

### P2：柳树compose模式无倍率放大
**现象**：兰花在compose模式下叶长×1.75、叶基宽幅×2，但柳树没有
**影响**：柳树在折枝创作模式下太小，不可用
**建议**：为柳树也添加compose模式参数放大，或统一为可配置参数

### P3：compose模式植物生长时间过长
**现象**：枯木需要40秒，兰花需要25秒
**影响**：创作迭代效率低，每轮调整要等半分钟
**建议**：compose模式下提供"立即完成生长"选项（跳过动画直接出成品）

## 裁断

今天的创作尝试**未达7分门槛**，不上线。

最接近的是双丛兰（5.5/10），兰叶的笔意和飞白质感有进步，但核心问题是compose API不允许主动构图。这次尝试的价值在于发现了工具的关键缺陷——P0如果不解决，画房在墨园上的创作能力将持续受限。

这个P0恰好和今天讨论的Command Bus架构直接相关：如果墨园的操作都通过Command进行，那么"画一片兰叶""调整第三叶的角度""在t=0.3处加一朵花"都可以是独立的Command，AI和人都能精确控制构图。这不仅是架构整洁的问题，是创作工具能不能用来创作的问题。
