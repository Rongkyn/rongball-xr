## 发现（先证后改）

### 坑#25 阻塞式外部字体 → 页面可永久打不开（5 件实锤）
- 基线 boot：hou 在移动/桌面档 readyState **永久卡 loading**、画布停默认 300x150、主脚本未执行。
- 隔离实验：
  - 系统层 `curl fonts.googleapis` → 200 / 0.15s（网络可达）；
  - CDP 精确阻断字体域 → 立即 complete（证明病根是字体资源）；
  - 抓 Network 事件：浏览器里字体请求 `requestWillBeSent` 后**无响应、无失败、永久挂起**
    ——系统层可达 ≠ 浏览器层可达（独立网络栈/代理/证书）。
- 波及面 grep：hou / ink-2048 / ink-garden / ink-gomoku / tian-deng 共 5 件；
  后三件历史已做过 media=print / preload+rel swap「非阻塞」修复，但复测三跑两卡——
  **解析器插入的样式表（含 media=print / preload）都参与 DCL 延迟，Chrome 口径不稳定。**
- 正解：head 内联引导脚本 `createElement('link')+appendChild` 动态注入——脚本插入的
  样式表非解析器阻塞，不延迟 DCL/主脚本；字体后台静默加载，断网回落本地字体栈。
- 同批还修了 gallery/index.html、仓库根 index.html 的阻塞字体链。

### 坑#26 harness drag 的 Node 变量泄漏 + 假阳性 PASS
- 定位过程：同样代码 `s.q()` 手动执行成功、`s.drag()` 必败 → 问题在 harness。
- 根因：drag 页面模板内写 `var useMouse = o.mouse!==false`，`o` 是 Node launch 闭包变量、
  页面不存在 → 首行 ReferenceError、零事件派出，被记成 `{__evalError:'Uncaught'}` 吞掉。
- acc1006 ink-particles 的交互判定是 before≠after，而粒子持续随机自运动 → 假阳性 PASS。
  即 acc1004/1006 所有走 drag 的验收都被静默绕过。
- 已修：Node 侧算好 useMouse 再 JSON.stringify 进模板。
