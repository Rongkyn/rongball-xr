# P08 长卷寻灵 · 立项纸

> 作品池 ID：P08｜出口：产品（小红书 Builder Hub 国风小工具）+ 内容（墨灵 IP 游戏化亮相）+ 简历叙事
> 立项：2026-10-23 创作时间（补 10-21 欠账：为「国风vibecoding大赏」新立的活动件）
> 状态：立项（v1 原型排在 P01 之后；待主人圈选）

## 一句话定义

一幅可以横移展开的程序化水墨长卷，里面藏着 N 只水墨小灵物，点中找出来；每卷由种子生成、构图各不相同，30 秒一局。纯前端单文件，挂小红书笔记即点即玩。

## 为谁解决什么

- **用户**：刷「国风vibecoding」话题、喜欢古画找猫 / 清明上河图摆摊那类轻互动的玩家。
- **爽感链路**：点开即开卷 → 左右拖动画卷 → 发现藏在山石云水间的小灵物（点中：朱圈 + 灵物现身 + 计数）→ 找齐计时结算 → 「再开一卷」。
- **差异点**：
  1. 样板「古画找猫」是固定画找固定猫，看攻略即失效；我们的长卷是程序化生成，每卷灵物位置 / 山形 / 季节都不同 = 天然重玩与晒分理由；
  2. 灵物 = P06 墨灵 IP 的游戏化首次亮相，找灵物同时是角色认知铺垫，产品线与内容线互相导流；
  3. 21 件水墨算法资产（噪声山水 / 季节 / 流场）直接入画，别人模仿要重写一套渲染器。

## 平台约束

同 P01：Builder Hub 沙箱纯前端，零外部 API / 服务器 / 数据库。灵物形象 v1 用程序化简笔（墨点圆身 + 点睛），不依赖外部图片；P06 角色圣经定稿后可替换为正式形象（仍走内联 SVG/Canvas，不外链）。

## v1 最小版本

- 横卷：宽幅 canvas（如 2400×900 逻辑卷，视口裁切），触摸 / 鼠标拖动横移（惯性 v2，v1 跟手）
- 长卷生成：FBM 连续山脊多层 + 云雾 + 树木点景，种子确定性
- 灵物：5 只，藏于生成时保证的「可发现点」（山坳、岸边、树枝、石后、雾中），半隐半现（透明度 / 遮挡由生成器控制，保证公平：灵物至少 30% 身体可见、点击热区 ≥ 36px）
- 交互：点中 → 朱红圈定 + 灵物动一下 + 计数 1/5；误点不惩罚只留淡墨痕；找齐 → 结算（用时、卷号种子）→ 再开一卷
- 移动端 390 优先；零外链零依赖；零 JS 错误

## 不做（v1 边界）

- 不做排行榜 / 账号 / 云端存分（沙箱禁止，也不背 KPI）
- 不做复杂关卡编辑器；不做音效（v1，v2 可接 WebAudio 环境音，与 P02/P04 同源）
- 不做付费道具 / 提示卡商业化；提示功能 v1 给一次免费「灵物方向涟漪」
- 灵物不做 AI 生图（沙箱无 API），程序化形象先行

## 成功指标（第一款不背收入 KPI）

- 主指标：挂载使用次数、完成一局比例（开始找 → 找齐 5 只）
- 辅助：「再开一卷」重玩率、评论「求 XX 灵物 / XX 场景」需求、话题自然流量
- 简历口径：官方活动内的程序化生成小游戏（区别于固定素材 H5），讲「生成式玩法 + 公平性工程约束（可发现点保证）+ IP 一体化」

## 复用与被复用

- 复用：P01 抽出的 FBM 山脊 / 云雾渲染原语（P01 先行，P08 直接吃）；山居 / 山水间的季节配色经验；noise-lib（如原型阶段允许 lib 目录，上传期再内联合单文件）
- IP 接口：灵物形象与 P06 墨灵角色圣经对齐，P06 定稿后统一替换；P08 先反哺 P06「灵物在画中如何半藏」的设定素材
- 开源接口：长卷生成 + 可发现点保证算法是 P03 inkwash-engine 的 demo 候选

## 风险与对策

| 风险 | 对策 |
|---|---|
| 公平性：生成器把灵物画进死角 / 完全遮挡 | 灵物位置由「可发现点」白名单生成，验收脚本逐卷 10 卷断言：每只可见像素占比 ≥ 30%、热区可点 |
| 拖动手感差（沙箱手机浏览器） | touch-action 挂 canvas 本体（避坑#22/§L）；CDP touchDrag 真触摸验收（避坑#29）；跟手优先于惯性 |
| 与古画找猫同质化 | 主打「每卷不同 + 墨灵 IP + 完整文人画长卷质感」，笔记内容讲程序化生成，不讲「又一个找东西」 |
| 活动截止时间未公开 | 主会话已请主人刷话题页确认；P01 先行，P08 紧随，技术资产同源不浪费 |
