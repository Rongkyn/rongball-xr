## 一、本轮改了什么

### 1. 性能：高密度下自适应降档
此前植株增多时逐节递归重绘 + 每叶求风摆动，成本随株数上涨，中低端机会掉帧。本轮：
- 引入 `perfProfile()` 运行时画像，按设备内存 / CPU 核心 / 是否移动端给初始档位；
- 实时帧率监控（滑动窗口），连续低于阈值自动降档（关落叶、减风动刷新、降风动细节），帧率回升且持续良好才回档，带迟滞防抖；
- 高频路径削减重复计算（风场、摆动复用），减少逐叶重算。

效果（CDP 实测，见 `acc_baseline_desktop.json` / `verify_*.json`）：
- 桌面 4 株、稳态 `FPS 60.2`，无降档；
- 自动栽种 starter 3 株、点击 +1、清园两击确认均正常；
- 高密度压测在画像档位内不跌破 30。

### 2. 移动端：印章与双行植物栏重叠
移动端把桌面右侧植物栏改为底部双行全宽栏，但印章（`#sealCanvas`）仍定位在左侧中部偏下，与栏发生真实重叠（实测印章 bottom 830 > 栏 top 732）。
- 修复：移动端（≤640px）印章改定位到**右下角、双行栏正上方**（`right:14px; bottom:calc(env(safe-area-inset-bottom,0px) + 132px)`）。
- 复测：印章 bottom 728 < 栏顶 732，留 4px 间隙，无重叠；桌面布局不受影响。

### 3. 字体/加载：交互不阻塞于字体表
验收确认 IIFE/CommandBus 就绪不依赖字体表加载完成（`readyMs 5814`，字体加载状态 complete/不 complete 均可交互）。

## 三、本轮踩的坑（重要教训）

### 坑#16（回流 harness）：goto 重连后旧 WebSocket 未关 + eval 误报 Uncaught
- 现象：`goto()` 里因避坑#4 做了"先关连接再连"，但**旧连接只改了引用、没有真正 `close()`**，两个 WS 同时收消息；它们共用同一 `msgId` 递增池，极端情况下响应会错挂到新连接的 pending，`q()` 误报 `Uncaught`。
- 处理：
  1. `goto()` 重连前真正关闭旧 WS（`try{oldWs.close()}catch{}`）并清空旧 pending，避免双连接并存；
  2. `q()` 对 "Uncaught" 类瞬时 eval 错误加**最多 3 次、间隔 100ms 的自动重试**（页面态表达式幂等，真语法错误重试也不会误判为通过）。
- 已回流 `lib/cdp-harness.js`。

### 更深的真相：本轮"诡异 evalError"主要是验收脚本自身笔误，不是 harness/作品
在定位坑#16 时，3 连跑移动验收都稳定 FAIL，一度归因于竞态。加完整 exceptionDetails 后发现：
1. **大断言表达式里 `barBottom:Math.round(vp.h-barR.bottom)` 漏写了模板插值**，字面量 `vp.h` 被发到页面运行时 → `ReferenceError: vp is not defined`；
2. 修改印章断言时又引入两处语法笔误（`getComputedStyle(sealCanvas))` 多一个右括号、`return {...});` 多一个右括号）→ `Unexpected token ')'`。
这些都是**确定性**错误，只是 harness 把所有异常统一吞成 `Uncaught`，丢失了行列与描述，才显得像间歇竞态。
- 教训（已沉淀进方法）：
  - 断言报 Uncaught 时，**先看完整 exceptionDetails（含 lineNumber/description）再怀疑框架**；
  - 大段模板字符串表达式，发出前用 node 做一次语法自检，并核对每个变量都已 `${}` 插值；
  - "框架问题"假设必须有证据，避免把脚本笔误误诊为竞态而长时间空转。

### 提示语高度为 0 不是 bug
首屏引导 `.ink-hint` 在首次栽种后正常隐藏，验收后期取到 offsetHeight=0 属预期。断言已改为"存在且 display 非 none"的更稳判定。

## 四、过程档卫生说明
本轮调试期间在过程目录生成了约 170MB 的 Chrome `--user-data-dir` profile（`ig_*` 目录）和大量一次性 `probe_*.js`。已清理，仅保留：`acc.js`（画像采集）、`verify.js`（双端验收）、两份 verify JSON、`acc_baseline_desktop.json` 及关键 PNG。教训：Chrome 用临时 profile 应落到会话临时目录并随用随清，不要放进 git 工作树。
