## 二、六项规格落地

### 改动 1：出枝位置（§3.2.1）

| 项 | 旧 | 新 |
|---|---|---|
| 首枝阈值 | `firstNode = 0`（第一节即出枝） | `branchStartT = 0.40 + rand(s*60)*0.10`（40–50% 高度以下全光竿） |
| 高度度量 | `upFactor = ni / nodes.length`（按节点序号线性） | 按 `segLens` 累加得真实 `nodeT = cumH / totalH`，与节间距模型一致 |
| 跳过率 | `0.12 + rand*0.08 ≈ 12–20%` | `0.35` 固定 |
| 每节枝数 | 主枝 + 贴竿短枝（条件触发）+ 底部双枝 + 中叶等多源 | **每节最多 1 根主枝** |
| 左右 | 严格交替 | 交替为主，20% 概率连续同侧破机械感 |

### 改动 2：枝长梯度（§3.2.2）

| t 区间 | 旧（混乱、多分支） | 新 |
|---|---|---|
| t < 0.55 | 60–260（isLong 160+rand*100，compose 折 0.78） | **120–180px** 中部长枝 |
| 0.55–0.75 | 58–200（midLong 130+rand*70） | **80–130px** |
| t > 0.75 | 18–53 两段 | **30–60px** 顶部短枝 |

外层仍乘 `(isCompose ? Lmul*0.55 : Lmul) * (isMain ? 1.0 : 0.85)` 以保留画幅/竿相缩放。

### 改动 3：枝弧度（§3.2.3）

旧：单一 `droopRate` 全程同向累加，弧度小且形态单一。
新：7 段折线，三段目标角相对 `baseAngle` 的侧偏弧度为：

- 初始（前 1/3 起点）：`side*(0.61 + rand*0.35)` ≈ **35°–55°**，前段仅向中段过渡 30%，基本保持斜上；
- 中段（1/3–2/3）：线性过渡到 `side*(1.05 + rand*0.35)` ≈ **60°–80°**，弧向外展开；
- 末段（2/3–1）：线性到 `side*(1.40 + rand*0.35)` ≈ **80°–100°**，梢端微下垂（可略低于水平）。

每段以 `sl = bLen/7` 等长推进，配合 `drawBambooTwig` 内 4× 细分 + brushPath 平滑，视觉为有弧度的一笔，不是折线。

### 改动 4：雀爪精简（§3.2.4）

| 项 | 旧 | 新 |
|---|---|---|
| 位置 | upFactor<0.55 即可 | 仅 **t<0.55 的中部长枝**，且在主枝 **60–80% 处** |
| 概率 | 45%，可有 2 组 | **40%**，**每根主枝 0–1 组** |
| 组成 | 1–2 个雀爪（每个 1 根细枝） | **2–3 根细枝**，每根长 **15–30px** |
| 承叶 | 每个雀爪端 1 个叶簇 | 每根雀爪细枝端 1 个叶簇（共 2–3 个） |

### 改动 5：删除过度叠加（§3.2.5 + 二.2.3）

删除以下全部旧叶簇来源：

1. ❌ 贴竿短枝（`upFactor<0.50` 的 shortLen=12–22）+ 其叶簇
2. ❌ 主枝 35% 处中叶簇（`s+1000`）
3. ❌ 主枝 18% 处中叶簇（`s+2000`）
4. ❌ 底部贴根双枝 + 叶簇（`s+4000`，这是左竹底部大弯钩的元凶）
5. ❌ 梢头独立小叶（`tipP`，两点零长 twig 承 ren 字簇）

**P2 只保留两类叶簇来源**：主枝端 1 个 + 雀爪端 0/2/3 个。

### 改动 6：枝渲染分级（§3.2.5）

`drawBambooTwig` 渲染逻辑未改，仅通过 `depth` 和 `width` 新分级触发其原有"老枝焦浓飞白 / 中枝浓墨 / 新枝清淡"路径：

| 节点 t | depth | width（主/辅） | 渲染 |
|---|---|---|---|
| < 0.60 | 2（老） | 7.0 / 5.5 | `INK.jiao` + `brushPathFeibai` 顿挫飞白，钉头粗 |
| 0.60–0.80 | 3（中） | 4.5 / 3.5 | `INK.nong` + `brushPath` |
| > 0.80 | 4（新） | 2.6 / 2.0 | `INK.zhong`，清淡 |

雀爪细枝固定 `depth=3`，宽度为父枝 55%，渲染为中墨细笔。

## 五、已知问题 / 留给后续阶段

1. **dispatch options 透传 bug（与 P2 无关，归属 P4）**
   `addStem.execute` 只把 `seed` 和 `instant` 拷入 `plantOpts`，丢弃了 `heightMul/lean/stalkCount/scale`。
   实测三竿 `hMulOpt` 都返回 1，`stalkGrade` 都被判为 `sub`。这是 P1 之前就存在的 Command Bus 问题，按规格 P2 不修；P4 构图阶段必须修，否则三竹等高三竹篱笆问题无法解决。

2. **雀爪承叶数偏多**
   设计书 §3.2.4 文义"雀爪=2–3 根细枝，端承叶簇"，当前实现是每根雀爪端一个叶簇，最多一主枝多出 3 个叶簇。若 P3 叶重写后觉得冠部过密，可把整组雀爪合并为 1 个共享叶簇。

3. **hasLeaf 计数与新逻辑表面不一致**
   运行时 `leaves` 计数比 `主枝端数 + 雀爪端数` 多 2。排查后确认是 `Plant` 构造期或历史路径残留（非本次新代码），不影响视觉；P3 重写叶系统时统一审计。

4. **枝与竿视觉穿插**
   新长枝斜出外展，左右竹的枝在画面中段可能交叉。这是宋画常见的"穿插"，P4 构图阶段会通过调整三竹位置/高度/藏露来优化。
