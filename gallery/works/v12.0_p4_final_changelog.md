## fix6：hScale generator defect（双环修复）

**症状**：fix5 时辅/远竹在 compose 模式下高度异常矮，主竹高大、辅远缩成苗。

**根因**（1460 行）：
```javascript
const hScale = (composeLayout && composeLayout[s]) ? 1.0 : (isMain ? 1.0 : (0.60 + rand(s*17)*0.15));
```
- compose 模式下 curHMul 已控制各竿高度比例，但旧代码对非主竹再乘 0.60-0.75 缩减
- 形成 curHMul × hScale 双重缩减，远竹实际高度仅主竹 30%
- AIOS bootstrapping 路由判定：**generator defect** → 改生成器重新产出

**修复**：compose 模式下 hScale=1.0，让 curHMul 独占高度控制。

**双环产物**：
1. 新增 `?skeleton=1` 骨架预检模式：彩色线框 + 几何指标 overlay，30 秒看构图
2. Bootstrap receipt 存 `BOOTSTRAP_RECEIPT_p4_hscale.md`
3. 修复方案可复用于松/柳/梅生成器（共用 compose 布局代码）

## farLean floor bug 根因（fix9 诊断）

```javascript
const leanAngleBoost = (composeLayout && composeLayout[s]) ? 0.80 : 0.08;
const baseAngle = -Math.PI/2 + tilt + (curLean || 0) * leanAngleBoost;
```

- compose 模式下 lean 经过 ×0.80 缩放
- farLean=0.17 × 0.80 × 57.3° = **7.8°**（不是注释声称的 9.7°）
- 要达 9.7° 硬下限，farLean 需 ≥0.212
- 这是 fix8 注释与实际不符的文档 bug，属 output defect

## fix10：hybrid 策略（终审通过）

**决策**：fix9 贪多嚼不烂。回退构图参数到 fix8（已过线），保留 fix9 两个真实改进。

最终参数（fix8 构图 + 两个 bug 修复）：
- mainDX = 80 + _lr()*80（80-160，同 fix8）
- gap1 = 280 + _lr()*100（280-380）
- gap2 = 80 + _lr()*70（80-150）
- **farLean = 0.22 + _lr()*0.14**（0.22-0.36，×0.80 后实际 10.1°-16.5°，floor 真正生效）
- **竿基分级收笔**：
  - 主竹：焦墨钝笔横切椭圆（长短轴随机形变去戳印感）+ 3-5 苔点（一大+数小，错落）
  - 辅竹：重墨钝笔 + 2-3 苔点
  - 远竹：渐隐短线 + 1 淡点（远不见根，虚入纸面）

评审：大众 7.1 / 专家 7.24 / P0=0，相对 fix8 净改善 +0.22。

## Studio 双环复盘（强制）

### 单环（改产物）
- v12.0 P4 构图完成，三竹成丛、欹势顾盼、叶冠交织、基部落地
- 修复 3 个 output defect：gap1 过大、基部弹簧、farLean floor 未生效
- 新增竿基分级收笔模式（可复用于松/柳/梅）

### 双环（改 Studio 流程）

**做对的**：
1. **skeleton=1 骨架预检工具**（fix6 双环产物）：fix6b→fix10 共 5 轮迭代均使用，几何验算从"看水墨猜问题"变成"30 秒读数据"，显著提速
2. **双轨评审制度**：大众（路人直觉）+ 专家（专业诊断）多次捕捉到对方漏掉的问题——大众发现"小黑钉/吸管插纸"，专家发现 farLean floor 数学错误
3. **Maker/Checker 分离**：Curator 合议不护短，fix9 退步时果断回退
4. **AIOS bootstrapping 路由**：hScale bug 正确判定为 generator defect，避免在 output 层反复调参

**做错的（要改）**：
1. **fix9 违反单变量原则**：一次改 4 个构图参数，失败后无法定位是哪个参数导致退步。Studio 契约 ROI 五条铁律第 ② 条"单变量"被违反。**改进**：今后构图参数调整一次只动一个，即使 Curator 判断"几个一起改更快"也要拆
2. **注释与实际不符长期未发现**：farLean 注释写 9.7° 实际 7.8°，存在 3 个版本（fix7/fix8/fix9）都没被验算。**改进**：涉及角度/长度的参数注释，写完必须用 CDP 实测一组数据验证后再提交
3. **mainDX 平移治右白 ROI 低**：3 轮共平移 120px，右白仅改善 2%，最后 fix9 激进 60px 仍无质变。**改进**：留白问题应优先考虑"加元素破白"（出枝/印章/题跋），而非平移主体；平移只解决"裁切风险"，不解决"气韵流通"
4. **评审反馈中的"路人语言"未及时转译**：fix8 大众说"小黑钉"，fix9 修了但修成"吸管插纸"，因为没读懂路人真正说的是"三株根部语言不统一 + 苔点看不见"。**改进**：大众评审反馈必须由 Curator 转译为具体技术项再派工，不能照字面改
