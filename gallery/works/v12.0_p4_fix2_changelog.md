## 根因诊断

P4-fix1 虽然引入了三竹构图（主/辅/远）的 `composeLayout`，但有三处代码逻辑断链，使构图参数完全失效或反向：

1. `curLean` 已计算但**从未传入**竿的 `baseAngle`，竿身一律垂直。
2. 主竹走通用 20% 跳枝率，seed 差时**顶部叶簇暴跌到 4-5 组**，华盖不立。
3. 远竹 `baseYOff=280-360px`，配合 `totalH≈185px`，竿+叶冠几乎**完全出画**，只露 0-125px 叶尖，等于"无远竹"。

## Bug 1（P0）：lean 从未传入竿角度

### 位置
约 1451 行 `const baseAngle = -Math.PI/2 + tilt;`

### 问题
`curLean`（mainLean = 0.22-0.37、subLean = -0.18~-0.33）在 1427 行 `let curLean = lean;` 定义、1441 行 compose 分支赋值，但 1451 行使用 `baseAngle` 时**完全未引用** `curLean`。`tilt` 只有 ±0.01 rad（<1°），所以三竹竿身都垂直，"欹势"参数形同虚设。

### 修复
```javascript
const leanAngleBoost = (composeLayout && composeLayout[s]) ? 0.25 : 0.08;
const baseAngle = -Math.PI/2 + tilt + (curLean || 0) * leanAngleBoost;
```

### 效果
- compose 主竹：0.22-0.37 × 0.25 = **0.055-0.093 rad（3.1-5.3°）右欹**
- compose 辅竹：-0.18~-0.33 × 0.25 = **-0.045~-0.083 rad（2.6-4.8°）左欹**
- 非 compose 单竹：仅加 ~1° 自然微斜（× 0.08），不破坏单株观感
- `curLean` 作用域正确（let 在 for 循环顶部，1451 行同作用域可见）

## Bug 2（P0）：主竹叶量无保底

### 位置
约 1571-1579 行 skipRate 逻辑。

### 问题
主竹 `isMain=true, isShort=false`，走 `else skipRate = 0.20` 分支，20% 节点跳枝。seed 差时顶部叶簇暴跌到 4-5 组，主竹华盖稀疏，失去"宋画主竿顶叶如盖"的体量感。

### 修复

1. **降跳枝率**（1578 行新增）：
```javascript
if (composeLayout && composeLayout[s] && isMain) skipRate = 0.08;
```
主竹跳枝率 20% → 8%，叶簇数从 8-12 组提升到 11-14 组。

2. **顶部 3 节硬保底**（1581-1582 行替换）：
```javascript
if (isMain && ni >= nodes.length - 3) { /* 主竹顶部3节保底出叶，形成华盖 */ }
else if (rand(s*70+ni*13) < skipRate) continue;
```
主竹顶部 3 节（`ni >= nodes.length - 3`）永远不跳，保证华盖密度；矮竿原有的 4-5 枝中部保底逻辑保持不变。

### 效果
- 主竹顶部 3 节必出叶，华盖不再受 seed 影响
- 中下部仍保留 8% 随机省略，避免叶簇塞满成"竹叶球"
- 不影响辅/远竹、矮竿路径

## Bug 3（P0）：远竹 baseYOff 过大导致完全出画

### 位置
约 1401-1415 行 far 配置。

### 问题
画布高 1080，植物生长基准 y=860（距画布底 220px）：
- `baseYOff = 280 + _lr() * 80`（280-360px）
- → 远竹 base y = 1140-1220（已在画布外 60-140px）
- 远竹 `totalH ≈ 185px`（hScale 0.675 × hMul 0.575 × H 480）
- → 实际只露出 0-125px 叶尖，大部分 seed 下远竹"消失"

### 修复

| 项 | 旧值 | 新值 | 说明 |
|---|---|---|---|
| `baseYOff` | `280 + _lr()*80`（280-360） | `100 + _lr()*60`（100-160） | base y=960-1020，藏竿露梢 |
| `farHMul` | `0.50 + _lr()*0.15`（0.50-0.65） | `0.55 + _lr()*0.15`（0.55-0.70） | 略高使叶冠更可见 |
| `gap2` | `80 + _lr()*120`（80-200） | `100 + _lr()*120`（100-220） | 略增辅-远间距，避免过度重叠 |
| 注释 | "下移280~360px，竿身大部分被底部截断，只露顶部约1/3枝叶" | "下移100~160px，藏竿露梢（下部60%竿身藏于画布外/辅竹后，梢顶叶冠露出）" | 与实际行为一致 |

### 效果
- 远竹 base y=960-1020，totalH≈200-240px，梢顶叶冠（约上部 40%）完整露出
- 下部 60% 竿身藏于画布外或辅竹后，符合宋画"藏竿露梢"的远竹处理
- gap2 微增避免辅竹叶冠与远竹叶冠过度重叠，保持层次
- 留白约束（`this.x + farDX < 1200`）保持不变

## 设计说明

三个修复构成 P4 构图的"最后一公里"：
1. **Bug 1** 让"欹势"从纸面参数变成可见的竿身倾斜；
2. **Bug 2** 让主竹在任何 seed 下都立得起华盖（视觉重心）；
3. **Bug 3** 让远竹从"出画消失"变成"藏竿露梢"的宋画远端处理。

三者共同把 P4 构图从"参数已设但未连通"推进到"三竹有欹有让、有藏有露、有主有从"的完整状态。

后续 P5 可考虑的方向（不在本次范围）：叶-枝-竿的墨色梯度强化、风动一致性、雀爪分布密度等表现层细节。
