## 三、关键Bug修复（generator defect）

**`drawOrchidLeaf` 中 strokes/n 未定义**（ink-garden.html 第3273行）：
```javascript
// 原代码（从某循环复制出的残片，引用不存在的外部循环变量）
const _totalForTone = strokes;
if (n >= Math.floor(_totalForTone*0.55) && tone === 'nong' && this.rand(b.id*7+n*3) < 0.75) tone = 'dan';
```
```javascript
// 修复后（按叶序id稳定随机，保留浓淡穿插原意）
const _leafIdx = (b.id || 0) % 9;
if (_leafIdx >= 5 && tone === 'nong' && this.rand(b.id*7) < 0.75) tone = 'dan';
```
**影响**：此bug导致兰在所有模式下drawOrchidLeaf抛异常、完全不渲染。说明兰此前从未在compose模式下被真正测试过——这是单物种孤岛开发的盲区。
**验证**：专家确认四图兰叶均完整连续、浓淡压叠正常，bug修复通过。

## Studio双环复盘

### 单环（改产物）
- 修复兰drawOrchidLeaf的strokes/n残片bug，兰恢复正常渲染
- 7个构图变体（v2→v3a/b/c→final a/b/c）探索出final_a，最终Seed 2024过线
- 右白从48%降至25-35%（部分化解，未根治）

### 双环（改Studio流程）
1. **多物种compose必须做跨物种渲染冒烟测试**：兰的bug说明单物种验收通过≠组合可用。今后新增/迭代任何物种，强制在compose模式下与至少一个已有物种同框种植，CDP console开异常捕获确认无报错。
2. **CDP console异常捕获法沉淀为标准调试手段**：`Runtime.enable`+`Log.enable`后recv筛选`Runtime.exceptionThrown`，比肉眼看图找bug高效。已写入工具经验。
3. **评审视角差异是资产不是矛盾**：路人看"顺眼"、专家看"咬合"，两轨并行才能同时守住大众接受度和专业品质。Curator合议时取交集而非二选一——本作为试验作，Seed 2024专业过线即上线，Seed 123的"清爽"反馈记为v12.1疏密节奏优化的输入。
4. **试验作定位清晰降低了完美主义内耗**：开局就声明"不冲馆藏、压测机制"，使P1问题能从容入backlog而不阻塞交付。这个定位策略可复用于后续新机制验证。
