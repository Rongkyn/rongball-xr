# 从任意宿主接手课题

这是按需执行的读取流程，适用于有 GitHub 读取入口的 Agent 或人。
本文件不安装连接器、不启动后台任务，也不保证能唤醒某个平台的会话。

## 开工时

1. 读本仓 [AGENTS](../AGENTS.md)、[贡献指南](../CONTRIBUTING.md)和当前分支上的本入口。
   若来自未合并 PR，先记录 PR 与 head SHA；默认 main 可能还没有新入口。
2. 从用户指定的 Issue / PR 开始；读正文、最新回复、相连 PR、实际 head 和必要的版本化输入。
   没指定任务时才浏览 open Issues，找与自己能力相符且范围明确的课题。
3. 区分开放研究、待回应请求、已有执行者和待审查产物；检查是否已有自己的回复，避免重复接单。
   本地书签可帮助增量读取，但不能替代原 Issue，也不能覆盖其他宿主的任务记录。
4. 检查当前宿主的实际能力与授权：能否读取、评论、改文件、运行检查、调用浏览器或音频工具。
   缺少写入能力时提供待发送文本和链接；不得声称已回复。无法实听时只做源码/实验设计审查。
5. 用[交接格式](handoff.md)回应具体输入版本；先解决真实写入重叠，再在独立分支/工作树执行。
   同一课题允许多个不重叠研究，不将某位贡献者固定为其他人的下属。
6. 交付固定版本、验证结果与限制。整合者读回实际回复，并在原 Issue 记录采用、返工或待定的部分。
   只有满足该任务判据才关闭；局部完成不关闭整个研究课题。

## 宿主适配的最小接口

| 操作 | 有能力时 | 缺少能力时 |
|---|---|---|
| 读任务和输入 | GitHub connector、CLI 或受信任浏览器，核对 SHA | 用户提供公开链接/文本；标注无法实时核对 |
| 写回复 | 在当前用户授权下写 Issue / PR，随后读回事件 | 输出草稿，请用户转交；维持未发送 |
| 制作产物 | 已授权路径上的隔离工作副本，提交任务分支 | 返回建议或可审查补丁，标明未落库 |
| 独立检查 | 另一执行实例读取最终版本与证据 | 保持待独立审查，不把自检改名为验收 |
| 后续唤醒 | 仅使用已授权且验证可用的定时/事件接收入口 | 下一次会话主动读取；可人工触发 |

AIOS 是可选执行适配器。它可管理本地运行、资源和恢复，但不能替其他宿主制造回复。
本仓的课题与交付记录仍由 Issue / PR / commit 承载。
宿主更新、账号配置、定时轮询与 webhook 安装须另有授权及运行证据。

## 什么时候才算互通

首个真实试点见[水声协作](../research/water-audio-comparison/pilot.md)。
两位真实参与者应完成：固定版本请求 → 对方读取并回应 → 交付 → 独立检查 → 发起方处理回复。
结论可以是不采用；只要回复被正确消费，就能证明交流有结果。

同一会话的不同角色自述不能证明跨宿主交流。只做文件与模板校验时，报告“入口可读、运行未验证”。
只有定时/事件触发实际发生、任务被读取并有对应产物，才能报告自动接续；手动触发的试点只证明人工辅助协作。
